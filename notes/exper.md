# 首屏优化的技术路线

- 分段加载与骨架屏
  - 使用骨架屏或渐进渲染展示占位内容，避免空白页面。
  - 将关键资源（核心数据、首屏组件）优先加载，非关键资源延后加载。
- 分层渲染与虚拟化
  - 将看板、仪表盘等区域实现分层渲染，核心区域优先渲染。
  - 对列表/表格等高渲染区域应用虚拟化。
- 首屏数据下探与缓存
  - 采用服务端预聚合/分片数据，首屏只拉取必要字段。
  - 客户端引入本地缓存与请求去重，避免重复请求。
- 资源优化
  - 具体包括：图片懒加载、JS/CSS 按需加载、GZIP/压缩、CDN Tensor、开启 HTTP/2/3、缓存策略等。
- 渲染层优化
  - 组件颗粒度与异步组件分包，减少初始渲染的工作量。
  - 使用事件循环优化、避免在首屏做耗时计算。
- 监控与回退

  - 集成 Performance API、Lighthouse/Web Vitals 指标，设置阈值告警。
  - 出现异常时，配置降级策略和快速回滚路径。

- 关键技术点与落地方案
- 骨架屏实现
  - 在路由切换、数据尚未就位时渲染骨架组件，数据就位后无感切换为真实内容。
  - 骨架屏尺寸、形状与真实布局保持一致，避免布局抖动。
- 看板布局的分区加载
  - 拆分看板区域为独立的 Vue 组件或异步组件，首屏仅加载可视分区。
  - 对拖拽相关逻辑使用节流/防抖，减少首屏渲染压力。
- 看板拖拽与布局计算优化
  - 将布局计算放入 requestAnimationFrame 内执行，避免和浏览器竞态。
  - 仅在需要时更新 DOM，利用 Vue 的 shouldUpdate 与 key 唯一性控制重渲染。
- 数据请求优化
  - 对首屏数据采用分片策略：先取核心字段，后续字段异步加载。
  - 引入请求缓存与去重，避免重复请求。
- 表格与大数据量视图
  - 初始仅加载可见行，其他行按需滚动加载（虚拟化）。
  - 对聚合/合并单元格采用按需渲染策略，缓存计算结果。
- 性能回路与回退
  - 设置首屏完成事件标记，确保首屏时间在目标内。
  - 监控滑动、拖拽、筛选等高频操作的帧率，触发降级方案（如降低刷新频率、禁用动画）。

2. 表格虚拟化实现要点

- 数据分块加载（Chunking）：将数据按行分块，按需加载当前可见区域的块。
- 行虚拟化（Row Virtualization）：只渲染可见行及少量缓冲区行，其他行仅在滚动时加载到屏幕上。
- 列虚拟化（可选）：若列数很多，采用列虚拟化或按需渲染可见列。

- 关键实现要点：
- 可视区计算
  - 根据滚动位置和容器高度，计算需要渲染的行索引区间 [startRow, endRow]。
- 高度与占位
  - 使用容器的 scrollTop、rowHeight 等静态信息或自适应高度策略。
  - 预估总高度：totalHeight = rowHeight \* totalRows。
  - 使用一个“占位容器”来提供滚动条滚动体验，内部实际渲染的行在可视区内。
- 渲染数据源
  - v-for 渲染仅 [startRow, endRow] 区间的行数据。
  - 行对象应具备稳定的 key（如唯一 id）。
- 性能优化
  - 避免在每次滚动时重绘整行，尽量只改变需要更新的行。
  - 将复杂单元格的渲染逻辑延迟到进入可视区后再执行。
  - 对筛选、排序等操作时重新计算可视区并更新。
- 缓存与重复计算
  - 对常用计算进行缓存（Memoization），尤其是复杂单元格合并、聚合计算。
- 合并单元格与分组
  - 使用轻量级的虚拟化库逻辑模板，若使用现成库，确保与现有表格组件的事件兼容。
  - 合并单元格在虚拟化场景下需额外处理：确保合并范围的渲染逻辑与滚动高度一致。
  - 分组头部的滚动定位要与数据块对齐，避免错位。
- 交互体验
  - 拖拽排序、列宽调整在虚拟化下仍保持流畅，尽量将影响范围限制在可视区内。
  - 滚动时的占位高度与实际行高度需精确对应，避免跳动。
- 可访问性与稳定性
  - 提供键盘导航时的可滚动焦点策略。
  - 处理空数据、加载状态和错误状态的渲染。
- 与现有组件的集成
  - 如果使用第三方表格组件，优先开启其内建的虚拟化特性，或封装自定义虚拟化层以保持风格一致。
